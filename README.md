# 满分，但是。· 盲抽猜分版

A 抽一张 0–10 分的牌，自己看不到；只有 B 看到分数。B 选择或描述一个「这是满分男 / 满分女 / 满分追星线下，但是……」的情境，让 A 猜它对应几分。A 的答案和牌面完全相同，就算猜中。

## 玩法

1. 创建房间，发邀请链接或 6 位房间码，2–12 人加入。
2. 房主开始后，系统按加入顺序指定 A（猜分者）、B（描述者）。两人局每轮交换角色，多人局依次轮换，其他玩家围观。
3. A 点击盲抽，分数由服务端生成，只返回给 B。A 和围观者的网络响应都不包含答案或 B 的候选情境。
4. B 从四个系统灵感中选择，也可以编辑、自己打字，或点击「说话转成文字」。描述草稿持续同步给同房间的朋友。
5. B 确认描述后，A 从 0–10 选一个数字。翻牌后显示是否命中；命中时 A 和 B 各记 1 次默契命中。
6. 房主开始下一轮，最终展示全局命中数、个人参与命中次数与每轮回顾。

## 语言

页面右上角可选择中文、English、日本語、한국어。首次访问根据浏览器语言选择，之后记住当前设备的选择；每位玩家可各用自己的语言。规则、按钮、系统提示、题材、90 个不同的内置与首页示例情境均提供对应译文。

选择系统情境时，服务端识别同一情境的不同语言版本；其他玩家和回顾页会按各自语言展示。修改后的自定义内容及语音转字仅保留原文，不使用在线机器翻译。麦克风识别语言跟随页面选择，切换语言会停止当前识别。

## 功能

- 满分女、满分男、追星线下三种题材；124 个内置情境，按目标分数给 B 提供四个主观灵感，可刷新。
- 自定义描述最多 500 字，约每 800ms 同步一次草稿，其他客户端每秒更新；网络延迟时会更慢。
- 5 / 10 / 20 轮；房间 24 小时过期；刷新恢复会话。
- 角色权限、隐藏答案、单次猜分、草稿版本检查、数据库乐观并发更新。
- 描述或猜分的一方离开会跳过本轮，围观者离开不影响；房主可手动跳过或移出离线成员；房主离开自动转交。

## 语音转文字

`app/use-speech.ts` 使用浏览器的 `SpeechRecognition` 或 `webkitSpeechRecognition`，语言为普通话，开启连续识别和中间结果。点击按钮才申请权限，停止、切换轮次或离开页面时终止识别。文字可以在停止后手动修改。

这是语音转文字，不是实时语音通话。浏览器或系统可能把音频发送给其在线语音识别服务；本站不接收或储存音频，只保存房间的描述文字。并非所有浏览器提供该接口，识别服务也可能因权限、网络或设备不可用；界面会提示改用手动输入或键盘语音输入。

## 本地运行与验证

Node.js >=22.13，npm。

```sh
npm ci
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_fluffy_roland_deschain.sql
npm run dev
```

首次本地运行应用已有迁移，已经应用过的无需重复。开发服务器地址以终端输出为准。

```sh
npx tsc --noEmit
node tests/run-local.mjs
# 可选：针对正在运行的开发服务器执行同一套接口测试
node tests/integration.mjs http://localhost:5173
```

本地测试使用真实 SQLite 和一个异步 D1 适配器运行实际 HTTP 处理逻辑，覆盖答案保密、三种角色权限、草稿文字同步、过期版本拒绝、并发更新、只允许一次猜分、准确命中、角色轮换、跳过、房主转交和重新开局。测试不会验证真实麦克风识别质量；需要在支持语音的设备上实测。

## 部署与结构

React 19 + Vinext + Cloudflare Workers + D1。`.openai/hosting.json` 声明托管身份与 D1 绑定，部署产物是 `dist/`。GitHub Pages 无法运行联机后端，需要支持 Worker 和数据库的托管。

- `app/game.ts`：游戏状态机与按角色裁剪的公开房间视图。
- `app/api/game/route.ts`：HTTP 接口、会话校验和数据库并发更新。
- `app/page.tsx`：建房、邀请、房间轮询、成员与整局回顾。
- `app/round-view.tsx`：抽牌、描述编辑、草稿同步、猜分与翻牌。
- `app/use-speech.ts`：浏览器识别与麦克风生命周期。
- `app/questions.ts`：三类内置情境。

## 会话与隐私

玩家用昵称加入，服务端生成不可猜测的会话令牌，保存在该浏览器本地。知道房间码的人可以加入，因此房间不适合存放敏感信息。昵称与描述对房间成员可见，分数在揭晓前只对描述者可见。

浏览器刷新会恢复当前会话，更换设备或清除数据后需要重新加入。房间创建 24 小时后不可访问，后续建房时清理过期记录。新规则使用 rules=2；旧规则房间返回 410 并提示创建新房，不迁移正在进行的旧玩法。

项目面向小范围朋友局，尚未配置大规模公开服务的限流和内容审核。
